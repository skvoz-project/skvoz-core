# Пример IPC на Python

`skvoz_ipc.py` использует Python 3.9+ и стандартную библиотеку для
[IPC v1](../../../docs/daemon-ipc.md). Это адаптер с ограниченными очередями;
повторное подключение и выдача профилей остаются за приложением.

С работающими демонами и принимающим обработчиком:

```sh
SKVOZ_SOCKET="/absolute/private-directory/core.sock"
printf 'hello' | python3 src/clients/python/echo.py --socket "$SKVOZ_SOCKET" --peer 0
```

Укажите свой абсолютный путь к закрытому сокету. `echo.py` принимает до
65 536 бинарных байтов stdin, включая пустой ввод, и печатает ответ с обратным
порядком байтов. JOIN обеспечивает готовность участника; SEND сохраняет непринятый
остаток; FINISH допускает ответ после EOF. CONSUME следует после записи вывода.
Преждевременное завершение с неполным ответом считается ошибкой.

Очередь полученных событий ограничена 4 096 элементами и 8 МиБ; приложение должно
её опустошать. Получение DATA не возвращает кредит. Код 4 при `consume` означает,
что дескриптор уже освобождён; это очистка, а не подтверждение обработки.
Новая IPC-сессия не получает старые дескрипторы и данные. Метаданные, принятие
и отклонение входящих запросов определяет приложение.

Rust-проверки daemon/IPC и реальной TLS/NATS бинарной границы описаны в
[инструкции сборки](../../../docs/getting-started.md#потребитель). Они не запускают
этот Python-пример; его команда приведена выше.
